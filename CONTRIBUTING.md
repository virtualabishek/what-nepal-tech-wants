# Contributing

Thanks for wanting to help. Here's how to add a job to this repo.

---

## What makes a good addition

- It's a **real job posting** from a Nepal-based company (or remote role targeting Nepal devs)
- It has meaningful tech requirements — not just "know Python" but actual specific tools/skills
- You've read it yourself and can write a breakdown that's honest, not just a copy-paste

---

## How to add a job

1. Fork this repo and create a new branch
2. Create a file under `/jobs/YYYY-MM/` following the naming pattern:
   ```
   role-name.md
   ```
   For example: `jobs/2026-10/postgresql-dba.md`

3. Use the template below as your starting point
4. Open a PR — keep the PR description simple, just mention the role and date

---

## Template

Copy this and fill it in:

```markdown
# [Role Title]

**Posted:** [Month DD, YYYY]  
**Location:** [City or Remote]  
**Experience Required:** [X+ years]  
**Education:** [Requirements]  
**Source:** [Link to posting if still live, or "LinkedIn / BDJobs / etc."]

---

## What they actually want

[Your honest read on this role. Is it senior? Is it entry-level dressed up as something scary? What's the core thing they care about?]

---

## Tech Stack Breakdown

### 1. [Technology Name]

[Explain what this is, why it's in this job, what level of knowledge they seem to want]

**Where to learn:**
- [Resource 1]
- [Resource 2]

---

## Honest Assessment

[Is this role realistic for someone with X years? What's hard? What's learnable?]

---

## Resources Summary

| Topic | Resource |
|-------|----------|
| [topic] | [link] |

---

*Added by: [@virtualabishek](https://github.com/virtualabishek)*
```

---

## A few guidelines

- **Don't just paste the JD** — break it down, explain it, give your read on it
- **Link to real resources** — official docs, reputable blogs, not random YouTube spam
- **Be honest** — if a requirement looks unrealistic or is just filler, say so
- **Don't include company names if the posting is anonymous** — respect that
- **Keep it readable** — write like you're explaining it to a smart friend, not writing a textbook

---

If you're unsure whether something fits, just open an issue and ask.
